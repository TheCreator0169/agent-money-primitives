The problem

Most agent finance code is prompt-shaped: "track your expenses carefully." That fails silently. A rounding bug or a sign error produces plausible-looking numbers that are simply wrong, and nobody notices until a reconciliation fails weeks later.

This is the code shape instead.

Pay-per-call endpoint

from agent_ledger import Paywall, PaymentError

pw = Paywall(payee="YOUR_ADDRESS", price="0.001", decimals=6)

@app.route("/v1/data")
def data():
    proof = request.headers.get("X-PAYMENT")
    ref   = request.headers.get("X-PAYMENT-REF")
    if not proof:
        return pw.issue_challenge(resource="/v1/data"), 402
    try:
        pw.verify(proof, resource="/v1/data", reference=ref)
    except PaymentError as e:
        return {"error": str(e)}, 403
    return {"data": "..."}

The reference is the part people skip. Skipping it is how you give your product away: any past transfer into the address becomes a valid payment proof. tests/test_paywall.py::UnboundPaymentTests reproduces that exploit in miniature.
